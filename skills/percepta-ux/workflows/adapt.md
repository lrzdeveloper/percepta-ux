# Adapt

Establish the original and target use: platform, supported inputs, available space,
text scaling, usage context, and the task to preserve. Use
[Product context](../references/product-context.md) for material constraints.
Missing design documents do not authorize a redesign or migration.

Specify how navigation, information relationships, controls, and recovery remain
usable in the new context. Retain critical data, recognizable actions, state,
and a way back. Consider a detail view or alternate presentation when content
cannot fit; account for extra navigation instead of merely hiding columns.

Read [Fitts](../references/fitts.md), [Hick](../references/hick.md), and
[Postel](../references/postel.md) only where they affect the intervention.
Honor native conventions for native targets; consult current official guidance
for exact platform API or conformance claims. Do not turn web units into native
minimums. Use [Review loop](../references/review-loop.md) to check the target task.

Done: deliver the requested proposal or implementation, preserving meaningful
capability with appropriate input alternatives and accurate verification limits.
