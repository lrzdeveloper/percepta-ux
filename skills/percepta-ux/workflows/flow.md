# Flow

Define actor, trigger, goal, commitments, and authoritative endpoint. Trace the
main path and consequential alternatives: back, correction, interruption, rejection,
unknown outcome, and exit. Show what persists and how work resumes.

Read [Decision patterns](../references/decision-patterns.md) for conflicting costs,
[Tesler](../references/tesler.md) for displaced complexity, and
[Peak-End](../references/peak-end.md) for closure when relevant. Preserve existing
flow terminology. Use a state table or diagram only when it clarifies the request.

Done: the requested flow specification or implementation connects important paths,
retains useful work, and separates acknowledgement from actual completion.
