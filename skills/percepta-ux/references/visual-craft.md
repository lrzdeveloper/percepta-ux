# Visual craft in service of the task

## Establish the visual contract

Identify the surface's purpose: deciding whether to engage, operating a tool,
reading material, or exploring an experience. A marketing page and an operator's
dashboard need different density, expression, and pace. Honor the actual brief,
audience, content, and platform rather than applying a single premium look.

Inspect existing design tokens, components, neighboring screens, and known brand
rules. Preserve them during refinement. For an authorized redesign or new product,
choose a coherent visual direction and make its type, palette, composition,
imagery, icon, and motion choices explicit. A collection of attractive references
does not by itself establish a system.

For a new surface, redesign, or conflicting project guidance, use
[Product context](product-context.md); missing design notes alone do not reset the
existing visual world.

## Make hierarchy legible

- Start from task and information priority. Give the dominant action or message
  adequate prominence; quiet competing elements before enlarging everything.
- Use a deliberate type hierarchy, readable measures, appropriate weight, and
  line breaks that preserve meaning. Keep labels useful and body text readable
  across available widths and text scaling.
- Use spacing and alignment to communicate relationships. Put related content
  together and separate distinct tasks. Grouping does not require a card around
  every block; a dense expert surface may benefit from flat, aligned information.
- Make icons consistent in family, weight, optical scale, and role. Keep labels
  for ambiguous actions. Color and animation can reinforce meaning, while text
  and semantics preserve it across perception and input differences.
- Preserve useful data density, factual copy, and recognizable state. A visually
  sparse page that forces extra search or memory work has not become simpler.

## Give expression a product-specific reason

Use imagery, composition, material, or motion to explain the subject or support
the intended experience. Differentiate the product through meaningful choices
rather than copying a fashionable library's entire visual language. Repeated
cards, badges, gradients, giant headlines, or restrained monochrome can all work
when the brief earns them; they are neither automatic recipes nor universal bans.

Treat reference examples as evidence of a possible composition, not evidence of
conversion, trustworthiness, or user success. Keep functional clarity distinct from
visual novelty. Do not add unsupported claims or invented product data to make a
layout look complete.

## Review the rendered work

When the implementation and tools are available, inspect the actual output at
representative widths and affected themes, with realistic text and data. Compare
the intended hierarchy with what is visibly prominent. Check cropping, overflow,
wrapping, focus, selected/disabled states, and important empty/error/loading states.
Batch visible defects, fix them, and look again after meaningful changes. A
source-only check cannot establish rendered quality.

For an image or screenshot alone, give a useful visual critique and identify what
requires runtime inspection. Avoid a mandatory redesign workshop for a small
alignment fix. Match the work and verification to the requested scope.

Use [Review loop](review-loop.md) to compare the promised change with the result
and distinguish source checks from rendered behavior.

## Relationship to the psychology core

Use aesthetic craft to support recognition, attention, comprehension, and a good
emotional experience. Validate the task separately using [Aesthetic-Usability](aesthetic-usability.md).
If minimal styling removes context, revisit [Hick](hick.md) and [Miller](miller.md).
If visual emphasis changes a meaningful choice, revisit [Ethics](ethics.md).

This is Percepta's original execution guidance. Use [Reference selection](reference-selection.md)
when an outside example can resolve a specific gap.
