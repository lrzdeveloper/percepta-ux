# Decision patterns: resolve the actual tradeoff

## Separate costs before choosing a law

| User cost | First lens | Different question to check |
|---|---|---|
| Learning an unexpected behavior | Jakob | Is the existing convention suitable for this audience? |
| Acquiring a control | Fitts | Is deciding which control to use the real obstacle? |
| Remembering something no longer visible | Miller | Can state remain available? |
| Choosing or classifying alternatives | Hick | Will grouping or labels help more than removal? |
| Translating input into a rigid machine format | Postel | Is the interpretation actually unambiguous? |
| Repeated mechanical work or hidden complexity | Tesler | Who does the displaced work and error recovery? |
| Waiting or uncertain action outcome | Doherty | Is feedback truthful about completion? |
| Missing meaningful information | Von Restorff | Is salience mistaken for understanding? |
| Positive impressions masking difficulty | Aesthetic-Usability | What did participants actually do? |
| Distress or unresolved ending | Peak-End | Is the entire task actually complete? |

These are diagnostic starting points, not exclusive categories or a scoring model.

## Common conflicts

**Visible expert commands versus a sparse menu.** Keep frequent work discoverable
and group it meaningfully. Compare full task time and error rate, including the
extra navigation introduced by hiding. Hick does not automatically win over
recognition, learned behavior, or expert efficiency.

**A fast action versus a consequential mistake.** Acknowledge immediately; add
review where consequences justify it. Use reversible optimism only when failure
can be handled safely. Speed, truth of state, and deliberation can coexist.

**A novel interaction versus familiarity.** Identify the specific benefit of the
new pattern, preserve recognizable anchors, test relevant tasks, and provide a
reasonable transition. Novelty should earn its learning cost.

**A distinctive CTA versus an informed choice.** Use hierarchy to clarify the
task while retaining readable costs, alternatives, and refusal. Prominence is
not consent. Check understanding before optimizing a click metric.

**Generous input versus a precise result.** Normalize harmless variation. For
ambiguous dates, amounts, identities, or destinations, show the interpretation
and resolve uncertainty before commitment. Keep validation and authorization.

**A memorable ending versus a broken middle.** Repair avoidable negative peaks,
preserve work, and resolve failures before adding celebration. Measure actual
outcomes and recalled experience as separate results.

**Removing controls versus transferring complexity.** Track work shifted into
setup, another role, prompting, verification, support, or later correction. Retain
critical visibility and meaningful escape routes when using abstraction.

## Match the scope

For a component, inspect its labels, hit area, focus, states, consequences, and
recovery. For a form or onboarding flow, also inspect input burden, sequencing,
state preservation, progress, contextual help, errors, and completion. For a
navigation or dashboard review, include user vocabulary, frequent tasks,
recognition, hierarchy, density, meaningful status, and expert repetition.
For an end-to-end journey, include handoffs, delay, failure, support, closure,
and exit. These are prompts to investigate relevant conditions, not claims that
all states exist in every product.

## Decide with evidence

Choose the intervention that best supports the actual task under its constraints.
Explain its benefit, cost, failure behavior, and test. A principle is a hypothesis
generator; observed research and genuine platform constraints can override a
superficial application. If evidence is insufficient, make a reversible proposal
and define the observation that would change the decision.
