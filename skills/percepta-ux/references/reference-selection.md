# Reference selection: extract a useful idea

## Start with the gap

Identify what the existing interface cannot yet do well: clarify a decision,
communicate state, support an input method, or express the product's character.
Inspect existing primitives and tokens first. Browse only when an outside example
can resolve that gap; the skill's guidance works without a reference catalogue.

Choose candidates by task, platform, visual direction, source access, and cost.
A polished demo demonstrates a possible presentation. It does not establish task
success, accessibility, reliable service integration, or production performance.
Distinguish a primitive, a compositional pattern, a visual effect, and a complete
workflow before deciding what to borrow.

## Abstract, then adapt

Describe the useful behavior in ordinary terms: what triggers it, what changes,
what the person learns, and what remains operable. Separate that idea from its
colors, assets, framework, and timing constants. Implement the smallest fitting
version in the user's existing stack. A reference written for another framework
does not justify introducing that framework for one control.

Keep one coherent visual direction rather than combining incompatible styles.
Use [Visual craft](visual-craft.md) for hierarchy, [Components](components.md) for
the state contract, and [Interaction patterns](interaction-patterns.md) when the
idea involves tactile feedback, changing labels, undo, uploads, or persistent results.

## Inspect only what is available

For an actual code-adoption decision, inspect current source and official docs
for exact APIs, dependencies, licensing/access, client boundaries, and maintenance.
State what was inspected and which behavior remains untested. A marketed MCP,
registry, exporter, or companion skill is not an available tool until the current
environment exposes it and the requested task warrants its use.

Use authorized access. When source is unavailable, offer an original implementation
of the described interaction or a fitting accessible alternative; do not claim
exact reconstruction, bundle restricted assets, or invent API details. A reference
request does not itself authorize installation, purchasing, or configuring tools.

## Leave a useful decision record

For a meaningful selection, record the gap, chosen approach, inspected evidence,
adaptation to local tokens/stack, dependencies/access conditions, and actual checks.
If the user asks for outside sources, provide a small relevant shortlist based on
current evidence. Otherwise deliver the adapted solution without an unsolicited
inspiration bibliography. Retain attribution required by any code or asset license
and cite research or standards when they support a factual claim.
